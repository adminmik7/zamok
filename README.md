# Zamok

Менеджер паролей для Android — функциональный аналог SafeInCloud, написанный с нуля.
Личный проект, без синхронизации и без выхода в Play Store.

## Стек

Версии зафиксированы и проверены на совместимость (октябрь 2026):

| Компонент | Версия |
|---|---|
| Gradle | 9.6.0 |
| Android Gradle Plugin | 9.4.1 |
| Kotlin | 2.3.21 |
| Compose BOM | 2026.04.01 |
| compileSdk / targetSdk | 36 |
| minSdk | 26 (Android 8.0) |
| JDK | 17 |

AGP 9.x заменил классический DSL блока `android {}` на новый. Проект пока остаётся на классическом:
сборку возвращают `android.newDsl=false` и ещё несколько переключателей совместимости в
`gradle.properties`. Сам AGP помечает их как deprecated и убирает в 10.0 — переезд на новый DSL
отложен, а не сделан.

## Сборка

Сборка только локальная: приложение ставится на телефон вручную, а один канал лучше двух — APK из
CI подписывался другим ключом и не вставал поверх локального без удаления приложения, а удаление с
выключенным бэкапом уносит хранилище.

Всё окружение лежит в `.toolchain/` внутри проекта и в git не попадает; `build.cmd` подхватывает
его сам, системный JDK и правка `PATH` не нужны:

```
build.cmd                          сборка debug APK
build.cmd clean                    очистка
build.cmd :app:testDebugUnitTest   тесты
```

Готовый APK ложится в `output\zamok-debug.apk`. Без аргументов `build.cmd` собирает именно его,
с аргументами — передаёт их обёртке Gradle как есть.

В `.toolchain/`: JDK 17 (Temurin), Android SDK (`platforms;android-36`, `build-tools;36.0.0`) и
домашний каталог Gradle с дистрибутивом 9.6.0 и кэшем зависимостей. `local.properties` указывает
на этот SDK, `build.cmd` ставит `JAVA_HOME` и `GRADLE_USER_HOME` и зовёт `gradlew.bat`.

APK подписывается ключом `%USERPROFILE%\.android\debug.keystore`: он создаётся один раз и дальше не
меняется, поэтому новая сборка встаёт поверх предыдущей обычным обновлением.

Обёртка (`gradlew`, `gradle-wrapper.jar`, Gradle 9.6.0) закоммичена — генерировать её отдельно не нужно.

## Формат vault-файла

Один файл содержит всю базу. Заголовок `ZAMOK1`, версия, счётчик итераций, соль, затем
завёрнутый ключ хранилища и зашифрованный payload. Мастер-ключ из пароля не шифрует данные
напрямую — он заворачивает случайный ключ хранилища, поэтому смена пароля не перешифровывает
payload. Заголовок служит AAD завёрнутого ключа, так что ни один параметр KDF не подменить;
payload привязан к файлу самим ключом хранилища.
Подробности — в KDoc `VaultFile.kt`.

## Резервные копии

Копия — это тот же файл хранилища целиком, а не отдельный формат. Он уже зашифрован мастер-паролем,
поэтому отдельный пароль для копии придумывать не нужно и забывать нечего. Файл сохраняется через
системный диалог (Downloads, Google Drive, USB — что угодно), а восстанавливается выбором файла и
вводом пароля **той копии**. Отсюда же и ограничение: копия открывается только в Zamok — формат
свой, в другом менеджере паролей её не прочитать.

Восстановление перезаписывает хранилище, но только после того, как копия открылась и её содержимое
разобралось. Неверный пароль, обрезанный файл, чужие байты — хранилище остаётся ровно таким, каким
было. Это единственная операция в приложении, которая может стоить всех паролей сразу, поэтому
проверка идёт до записи, а не после.

## Вход

С записанным отпечатком хранилище открывается **только** отпечатком: диалог появляется **сам** при
возвращении в приложение, кнопки нажимать не нужно, поля пароля на экране нет. Диалог вызывается в
`onResume` активити, а не из композиции: платформенный диалог приклеивается только к уже показанному
окну, а первая композиция проходит раньше, чем активити перейдёт в resumed, — из-за этого вызов из
composable мог не показать ничего. Мастер-пароль остаётся за ссылкой «Ввести мастер-пароль» — не
потому, что он равноценен, а потому, что сломанный датчик или уничтоженный системой ключ иначе запер
бы владельца в собственном хранилище навсегда.

Отпечаток включается только в **открытом** хранилище: он запечатывает ключ хранилища, а ключа нет,
пока хранилище закрыто. Пока отпечаток не включён, на экране входа об этом сказано прямо, а не
оставлено на догадки.

Пока диалог отпечатка на экране, автоблокировка не срабатывает: пользователь никуда не уходил, а
включение отпечатка требует открытого хранилища — запереть его ровно в этот момент значит сорвать
включение. Само «идёт диалог» ограничено минутой, а не ждёт колбэка: колбэк, который не придёт,
оставил бы хранилище незапираемым навсегда, а это хуже, чем лишний раз показать пароль.

## Главный экран

Сверху — поиск (по названию, логину, адресу, заметкам и меткам), рядом звёздочка избранного и фильтр
по категориям; порядок (по названию или сначала недавно изменённые) выбирается из меню в поле поиска.
Под поиском — вкладки по типам записей: показаны только те типы, которые есть в хранилище, плюс
«Все». Ниже — список, внизу — навигация: хранилище, безопасность, инструменты, поиск. Кнопка «+»
раскрывает веер типов записей, как в приложении-образце, а не открывает сразу диалог пароля.

Каждая строка: кружок с иконкой типа записи, название, вторая строка (логин → адрес → пароль, всегда
замаскированный) и код 2FA, если он для записи задан.

**Значка сайта нет и не будет.** Настоящие иконки сервисов — чужие торговые марки, а их загрузка
означала бы, что приложение спрашивает сеть про каждую запись в хранилище. Поэтому кружок с иконкой
типа записи: цвет считается из названия, одинаковый на всех устройствах и не меняется между запусками.

Тема — одна, тёмная, зафиксированная. Хранилище открывают и ночью: один набор контрастов,
выверенный один раз, лучше двух наборов, выверенных наполовину.

**Чего нет из образца:** значки сервисов (причина выше) и баннер о премиум-функциях — платных
функций в Zamok нет вовсе.

## Диалог записи

Сверху два выбора: тип записи (пароль, одноразовый код, платёжная карта, заметка, паспорт) и
категория — выпадающий список уже существующих плюс «Новая категория…» для той, которой ещё нет.
Категории предлагаются, а не вводятся по памяти: иначе «Банк» и «банк» становятся двумя разными
группами. Цветная точка рядом с названием — тот же цвет, что получает кружок записи в списке.

Новая запись открывается в том типе, который выбран в веере «+», и в той категории, которая сейчас
выбрана фильтром; оба выбора остаются в диалоге, поменять можно.

Тип записи хранится строкой. Незнакомый тип читается как обычная запись, а не ломает открытие
хранилища: файл пишет та версия приложения, которая установлена.

Внешний вид экранов повторяет SafeInCloud (com.safeincloud.free): вкладки по типам, поиск со
звёздочкой и фильтром, нижняя навигация, веер типов по «+», селекторы сверху в диалоге записи.
Второй образец — mSecure (com.mseven.barolo): тёмные поверхности, один синий акцент. Ассеты и
брендинг обоих не копируются — исходников нет, а логотипы чужие.

## Экспорт и импорт CSV

Файл CSV — это **открытый текст**: пароли в нём лежат как есть. Он нужен для переезда в другой
менеджер паролей и из него, а не для хранения — для копии есть «Сохранить копию», она зашифрована.
Приложение предупреждает об этом перед экспортом.

Экспорт пишет колонки `title, username, password, url, notes, category, tags, totp, favorite` в
UTF-8 с BOM (без него Excel в Windows читает кириллицу как попало), строки заканчиваются CRLF,
кавычки — по RFC 4180.

Импорт **добавляет** записи, а не заменяет хранилище. Записи, которые уже есть (совпадают название,
логин, адрес и пароль), пропускаются, поэтому тот же файл можно импортировать повторно без
дубликатов. Колонки ищутся по названию, так что файлы из Chrome/Edge (`name,url,username,password,note`),
KeePass (`Account,Login Name,Password,Web Site,Comments`) и Bitwarden
(`folder,favorite,type,name,notes,login_uri,login_username,login_password,login_totp`)
импортируются без правки, а неизвестные колонки игнорируются. Если строки заголовка нет, порядок
берётся по умолчанию: название, логин, пароль, адрес, заметки.

## Правила проекта

- Криптография не пишется руками. Только платформенные API (`javax.crypto`, Android Keystore)
  и проверенные библиотеки.
- Каждая фича, связанная с безопасностью, идёт с проверкой — не «вроде работает».
- `android:allowBackup="false"` остаётся выключенным: хранилище не должно уезжать в облачный
  бэкап или при переносе на другое устройство.
