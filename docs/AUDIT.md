# Аудит «Замка» — 22.10.2026

Версия на момент аудита: 1.11.9 (versionCode 23). Тестов на момент аудита: 178 в 10 файлах, зелёные.

Статусы: `[исправлено]`, `[открыто]`, `[решено не исправлять]`.

## Критично

### 1. Автоблокировка срабатывает внутри приостановленных сценариев `[исправлено]`

`document.addEventListener('visibilitychange')` вызывал `lockVault()` без проверки `autoLockSuspended`, а сам `lockVault()` флаг не смотрит. Любой системный пикер (файл, камера, галерея, share sheet) уводит активити в фон → `document.hidden` → `vault.lock()` → `this.key = null`. Следствия: импорт/экспорт падали с «Хранилище заблокировано», черновик редактора с выбранным фото исчезал.

Исправление:

- `src/main.js` — условие стало `document.hidden && state.settings.autoLockMs > 0 && !autoLockSuspended` (как в `onAppStateChange`).
- `src/ui/screens/editor.js` — выбор фото обёрнут в `suspendAutoLock()/resumeAutoLock()` через `beginPhotoPick`/`releasePhotoPick`; снятие приостановки по `change`, `cancel`, возврату фокуса окна и страховочному таймауту 180 с, ровно один раз.
- Сборка: BUILD SUCCESSFUL in 38s, тесты 178/178.

Остаточное поведение: пока системный пикер открыт, автоблокировка не срабатывает; после закрытия таймер стартует заново на полный интервал.

### 2. В релиз уходит debug-сборка `[открыто]`

`android/app/build.gradle` — у `release` нет `signingConfig`, `tools\publish-release.mjs` заливает `build\apk\zamok-debug.apk`. У debug-сборки `android:debuggable="true"`: доступ через `adb shell run-as`, отлаживаемая WebView через `chrome://inspect`, чтение SharedPreferences с подключённого по USB устройства. Вместе с п.3 это даёт чтение мастер-пароля и GitHub-токена.

План: завести keystore, собирать `assembleRelease`, публиковать `zamok-release.apk`.

### 3. Мастер-пароль и GitHub-токен читаются без биометрии `[открыто]`

`src/platform/native.js` вызывает `NativeBiometric.setData({key, value})` без `accessControl`. При `accessControl = 0` плагин создаёт ключ AES в Keystore без `setUserAuthenticationRequired` (только StrongBox и `setUnlockedDeviceRequired`), поэтому `getData()` возвращает секрет без отпечатка. `getMasterCredential()` и `getServerToken()` — обычные функции; токен GitHub к тому же кэшируется в `serverTokenMemory` навсегда и не сбрасывается при `vault.lock()`. Биометрия сейчас — только UI-гейт.

План: `accessControl: 2` + `authValidityDuration: 0` (в плагине есть путь через `AuthActivity`), либо шифрование мастер-пароля ключом с обязательной аутентификацией; сбрасывать `serverTokenMemory` при блокировке.

## Высокие

### 4. TOTP для нестандартных аккаунтов всегда неверный `[открыто]`

`parseOtpUri` возвращает `digits/period/algorithm`, но редактор сохраняет только `secret` и `issuer`, а показ вызывает `generateTotp(secret)` с дефолтами 6/30/SHA-1. Для 8-значных и SHA-256 аккаунтов код не подойдёт никогда. Хранить и прокидывать все параметры; `totpAccount` из URI тоже теряется.

### 5. Выход из редактора без предупреждения `[открыто]`

«Х», системный «назад» и жест выбрасывают набранное молча, включая сгенерированный пароль и фото.

### 6. Каждое изменение — полное перешифрование хранилища `[открыто]`

`Vault.persist()` шифрует весь массив `items`, `upsert`/`remove` вызывают его на каждую запись, удаление категории — N полных шифрований подряд. С base64-фото (до ~1 МБ на запись) это секунды. Нужен батч-режим: одна мутация — один `persist()`.

### 7. Таймеры очистки буфера обмена накладываются `[открыто]`

Экраны записи, карты и скидочной карты ставят независимые `setTimeout(clearClipboard)`: копирование пароля, затем номера карты — первый таймер стирает второй раньше срока. При `lockVault()` буфер не чистится вовсе. Нужен единый менеджер со сбросом таймера и очисткой при блокировке.

## Средние

- **Стоимость KDF не хранится в хранилище** `[открыто]`: `deriveKey(pw, salt)` без `iterations`, в `.zmk` это поле есть. Поднять 600 000 итераций, не сломав существующие хранилища, нельзя.
- **Импорт молча теряет дубликаты** `[открыто]`: дедуп по сигнатуре в `importPlain` работает и внутри самого файла; режим `replace` — это «слить в пустое», а не «заменить».
- **`Filesystem.downloadFile` помечен `@Deprecated`** в Capacitor 8 `[открыто]`: работает (возвращает `absolutePath`), но сломается при обновлении Capacitor. Проверки целостности и подписи скачанного APK перед установкой нет.
- **`copyButton` в `src/ui/components/form.js`** `[открыто]`: мёртвый код, пишет «Скопировано», но в буфер ничего не кладёт. Удалить, чтобы однажды не подключить.
- **Двойной тап «Сохранить»** `[открыто]`: создаёт две записи, нет ни флага `saving`, ни блокировки кнопки.
- **Импорт обычного JSON без пароля** `[открыто]`: файл, который не `.zmk`, вливается в хранилище без подтверждения паролем (legacy-поддержка).

## Проверено и в порядке

AES-GCM-256, PBKDF2-SHA-256 600k, случайные salt и IV на каждую операцию, неизвлекаемые ключи, `allowBackup=false` + `dataExtractionRules`, `usesCleartextTraffic=false`, `FLAG_SECURE` через `UpdatePlugin` по настройке, проверка диапазона `iterations` при импорте бэкапа, очистка модалок при блокировке, корректный `FileProvider` для APK, регистрация плагинов до `super.load()`.

## Отдельно: сборка

`tools\build-apk.ps1` сам собирает веб-часть: `npm run sync` (vite build + cap sync android) → `gradlew assembleDebug` → копирование APK в `build\apk\zamok-debug.apk`. Если веб-сборка падает, Gradle не запускается и скрипт выходит с кодом 1 (причина — в `tools\gradle.log`). Весь цикл правки: `npm test` → `powershell -ExecutionPolicy Bypass -File tools\build-apk.ps1`.
