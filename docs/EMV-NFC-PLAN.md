# NFC/EMV: чтение банковской карты — план реализации

**Статус:** реализовано 21.10.2026 (плагин, разбор EMV, модалка, тесты). Осталась проверка на реальной карте (этап 3).

## 1. Задача

Заполнить запись типа «Банковская карта» данными, прочитанными с карты через NFC телефона:
номер, срок действия, имя держателя.

### Что читается, а что нет

| Данные | Читаются? | Тег EMV |
|---|---|---|
| Номер карты (PAN) | да | `5A` (иногда усечённый) |
| Срок действия | да | `5F24` (YYMM) |
| Имя держателя | да | `5F20` |
| Страна выпуска | да | `5F28` / `5F2D` |
| CVV/CVC | **нет** | генерируется банком, на карте не хранится |
| PIN | **нет** | лежит в зашифрованном PIN-блоке |

Следствие: после считывания CVV остаётся ввести руками (один раз).

### Ограничения

- Часть банков не отдаёт PAN без проведения транзакции → приложение честно сообщает
  «карта не дала прочитать номер», номер вводится вручную.
- У карт с динамическим CVV номер может быть доступен, а CVV — всегда нет.
- Чтение PAN — чувствительные финансовые данные: в приложении они шифруются в хранилище
  и никуда не отправляются (приложение офлайн). Для публикации в Google Play потребуется
  политика использования платёжных данных.

## 2. Архитектура

Нативный слой — тонкий: умеет только «отправить APDU / получить ответ».
Вся логика EMV — на JS, чтобы её можно было покрыть обычными тестами vitest
и быстро чинить по живым ответам с реальных карт.

```
src/core/emv.js            разбор TLV, PPSE, GPO, записи, команда Get PAN (чистые функции)
src/core/emv-flow.js       оркестрация: сессия → PPSE → SELECT → GPO → READ → Get PAN
src/platform/native.js     readNfcCard() / nfcAvailable() — обёртки над плагином
src/ui/components/nfc.js   модалка «Поднесите карту к телефону» + анимация + лог
src/ui/screens/editor.js   кнопка NFC в поле «Номер карты», заполнение полей
android/.../NfcCardPlugin.java  сессия, reader mode, один обмен APDU
```

## 3. Нативный плагин `NfcCardPlugin.java`

Регистрация — в переопределённом `load()` у `MainActivity` (как `UpdatePlugin`):
`registerPlugin(NfcCardPlugin.class)` **до** `super.load()`, иначе JS увидит неизвестный плагин.

| Метод | Что делает |
|---|---|
| `isAvailable()` | `NfcAdapter.getDefaultAdapter() != null` и адаптер включён |
| `startSession()` | включает reader mode, ждёт тег, открывает `IsoDep`, возвращает `{sessionId, atr, techs}` |
| `transceive(sessionId, apduHex)` | один обмен APDU, возвращает `{response: hex, sw: "9000"}` |
| `endSession(sessionId)` | закрывает `IsoDep`, выключает reader mode |

Детали реализации:
- `NfcAdapter.enableReaderMode(activity, callback, flags, extras)` с флагами
  `FLAG_READER_NFC_A | FLAG_READER_NFC_B | FLAG_READER_NFC_F | FLAG_READER_NFC_V | FLAG_READER_SKIP_NFC_CHECK`.
- Callback приходит в binder-потоке → резолвить промис через `new Handler(Looper.getMainLooper()).post(...)`.
- Сессия живёт, пока карта в поле; на каждый `transceive` — свой таймаут (500–1000 мс).
- Общий таймаут сессии — 30 секунд, дальше `endSession` и ошибка.
- `IsoDep` берётся через `IsoDep.get(tag)`; при отсутствии — понятная ошибка «карта не поддерживает EMV».

## 4. Протокол чтения (JS управляет, натив исполняет)

1. **PPSE** — `00 A8 04 00 00 02 70 00` → разбор ответа: `6F` → `84` (DF) и `61` (шаблон приложения) → `4F` (AID).
   Список AID приложений карты.
2. **SELECT** приложения: `00 A4 04 00 <len> <AID> 00`.
   Типовые AID: `A0000000031010` (PPSE), `A0000000030040` (кредит), `A0000000030020` (дебет),
   `A0000000030000` (Global). Приоритет — из списка PPSE, иначе пробуем кредитный, потом дебетный.
3. **GPO** (Get Processing Options): `80 A8 00 00 00 <len> 83 <len> <PDO>`.
   Терминальные данные: `9F66 04 F000 F000 F000` (или `4F 00 0A 00 00`), `9F02 06`, `9F03 06`,
   `9F1A 02`, `9F35 00`, `9F36 00`, `9F37 04`, `95 05`, `5F2A 02`, `9A 03`, `9C 01`.
   Ответ: `77` → `50` (label), `84` (AID), `5F2D` (криптограмма), `57` (track 2),
   `9F0D`/`9F0E`/`9F0F` (SFI + смещение).
4. **Чтение записи** по SFI: `00 B2 <sfi|0x00> <record#> 00`
   (SFI 1–14 → `0x00 | sfi`), либо **READ BINARY** `00 B0 <offset> <len>`.
   Из записи/файла достаём: `5A`, `5F24`, `5F20`, `5F28`/`5F2D`, `9F1F` (AID), `8C`, `8F`.
5. **Track 2 (`57`)** — запасной источник номера и срока: `57` = PAN + `YYMM` + discretionary.
6. **Get PAN**, если номер усечён: проприетарная команда
   `80 A8 00 00 00 04 00 00 00 <len> 80 02 <cryptogram>`; при отказе — сообщение пользователю.
7. **Бренд** — по AID и префиксу PAN, совместимо с `cardBrand()` в `src/ui/screens/card.js`.

## 5. Разбор на JS (`src/core/emv.js`)

Чистые функции без Android — значит, покрываются тестами:

```js
parseTlv(hex)                       // дерево тегов
findTag(tlv, '5A')                  // поиск тега
parsePpse(response)                 // список AID
buildSelect(aid)                    // APDU SELECT
buildGpo(terminalData)              // APDU GPO
parseGpo(response)                  // {sfi, pan, expiry, holder, ...}
parseRecord(response)               // разбор записи/файла
parseTrack2(hex57)                  // PAN и срок из track 2
buildGetPan()                       // проприетарная команда
buildReadRecord(sfi, record)        // APDU READ RECORD
detectBrand(aid, pan)               // Visa / Mastercard / МИР
```

`src/core/emv-flow.js` — последовательность вызовов над плагином, результат:
`{ pan, expiry, holder, brand, raw }`.

## 6. Интерфейс

- В поле «Номер карты» — кнопка с иконкой NFC (рядом с уже привычной кнопкой сканера штрихкодов,
  используется существующая опция `action` у `field()` в `src/ui/components/form.js`).
- Модалка «Поднесите карту к телефону»: анимация волны NFC, кнопка «Отмена», таймаут 30 секунд.
- После считывания заполняются:
  - номер — сразу с пробелами: `0000 0000 0000 0000`;
  - срок — `ММ/ГГ`;
  - владелец — как есть.
  Плюс тост «Карта считана».
- Если телефон без NFC или NFC выключен — кнопка не показывается, при попытке — понятное сообщение.
- CVV остаётся пустым.

## 7. Разрешения и манифест

```xml
<uses-permission android:name="android.permission.NFC" />
<uses-feature android:name="android.hardware.nfc" android:required="false" />
```

`required="false"` — приложение остаётся доступным на телефонах без NFC.
Системного запроса разрешения не нужно (NFC — обычное разрешение).

## 8. Отладка

В модалке — кнопка **«Скопировать отладочный лог»**: полный обмен APDU (команда → ответ → SW).
Если номер не прочитался, пользователь копирует лог и присылает его — по нему допиливается
разбор под конкретный банк. Лог содержит номер карты и остаётся на устройстве.

Параллельно всё логируется в консоль (`console.info`), чтобы можно было снять через `chrome://inspect`.

## 10. Этапы

1. **Каркас**: нативный плагин (сессия, `transceive`) + `emv.js` + `emv-flow.js` + тесты на синтетических ответах.
2. **UI**: кнопка NFC, модалка с анимацией, заполнение полей, копирование отладочного лога.
3. **Проверка на реальной карте** — пользователь ставит APK, присылает лог → правка разбора под конкретные карты.
4. **Релиз 1.7**: версия, changelog, `tools\release-notes-1.7.md`, публикация на GitHub
   (скрипт `tools\publish-release.mjs`).

## 11. Риски

- EMV — большая спецификация; без живых ответов разбор не довести (отсюда этап 3).
- Разные банки ведут себя по-разному: разный порядок AID, разные ответы на Get PAN, часть карт
  не отдаёт PAN без транзакции.
- Проверка возможна только на физическом телефоне с NFC и реальной карте — у разработчика их нет.
- Возможна отмена на стороне Android: чтение NFC в фоне ограничено, но мы работаем в reader mode
  при активном экране — это разрешённый сценарий.

## 12. Что нужно от пользователя

- Настоящая банковская карта (несколько банков было бы идеально) и телефон с NFC.
- Готовность присылать отладочный лог из модалки, если считывание не сработало.
